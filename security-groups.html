1. Roles

The 6-tier role enum. No inheritance — every grant below is explicit.

RoleRankDescription
Manager 1 Full admin — user management, audit view + rollback, every module action.
Supervisor 2 Audit view, intake commit, equipment edit. No user management.
Employee 3 Intake view + import, equipment view. No commit, no admin.
Apprentice 4 Read-mostly — intake + equipment view.
Labour Hire 5 Minimal — own roster / timesheet only (no shell permissions today).
Subcontractor 6 External trade engaged for a job, not an agency worker. Minimal — same baseline as labour_hire.

3. Default security groups

Named bundles of extra permission keys, additive on top of a user's base role — not a role themselves. A fresh tenant starts with zero groups; these are the canonical starter templates eq-shell seeds on tenant creation.

GroupWhy it's cross-cuttingGrants
equipment_editors
Equipment editors
 Edit the plant & equipment list and calibration details. Add people here who maintain equipment but whose role normally only lets them view it. equipment.view equipment.edit
report_viewers
Report viewers
 View GM reports without being made a manager. Add supervisors or leads here who need to read reports. reports.view
project_managers
Project Managers
 Manage users, review Cards onboarding, and view the audit log without full manager admin rights. Promoted from a tenant-specific group (originally SKS) once it proved to be a common cross-cutting need, not a one-off. admin.list_users admin.edit_user admin.review_cards audit.view
Scope of this document: the canonical model only — the 6 roles, the full permission matrix, and the 3 default security-group templates, as defined in eq-roles. It does not include live, per-tenant group membership or tenant-specific (non-default) groups — those are created and managed per tenant in eq-shell's Access Control page (admin.manage_groups) and are not exported here.
